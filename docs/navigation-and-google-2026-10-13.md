# Navigation and Google sign-in — 13 October 2026

Every dynamic route previously used a prominent “Loading your next discovery…” fallback. Default Next Link prefetching stopped at that loading boundary. The six primary navigation links now request full route prefetching. Project cards, header links, and Explore links retain default lightweight prefetching and request the full destination on hover, keyboard focus, or touch intent. Long feeds do not eagerly fetch every project detail.

The fallback now uses a neutral, accessible page placeholder with a 200 ms visual grace period and reduced-motion support. Independent project-detail media, vote, saved-state, and owner-control reads run concurrently. Authentication, account restrictions, database authorization, and private no-store headers remain in place. This improves scheduling and perceived navigation; it does not guarantee zero waiting on slow connections or cold server requests.

Verification: 64 unit tests, 24 relevant desktop/mobile auth, Google, discovery, and publishing workflow checks, type checking, lint, and production builds passed. A dedicated production-mode browser check confirms a background Settings prefetch before the click and successful navigation to the correct authenticated profile. It does not claim that the entire streamed response has finished before the click, or establish a production latency benchmark. CI now runs this production-mode check.

Google OAuth uses project `ark-rage`, client “ARK Web”, production origin `https://ark-rage.vercel.app`, and the managed Supabase Auth callback. The user entered the client credentials into Supabase. An accidental `ARC` prefix in the Client ID caused `401 invalid_client`; correcting it resolved the error. Real Google consent returned to Explore as @sndp, and the session persisted into Settings. No client secret was stored in source or app environment variables by this setup.

The app requests only `openid email profile` and selects the Google account explicitly. Google Auth Platform is External / Testing with no test users. Google's documented basic-identity scope exception allows this login without adding users to the test allowlist: https://developers.google.com/identity/protocols/oauth2/production-readiness/overview . Google branding verification and replacing the Supabase consent hostname with a custom Auth domain remain separate branding work.
